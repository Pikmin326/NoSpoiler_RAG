# Spoiler-safe RAG — 초기 버전

## 이번 변경의 요점

기준: 커밋 `f46e7a1` 이후(미커밋). 상세 내용은 [CHANGELOG.md](CHANGELOG.md), 데이터 흐름은 [DATA_FLOW.md](DATA_FLOW.md)를 보세요.

- **소설 → 응답 자동화**: 소설 파일만 넣으면 `prepare`가 장 구조 인식 → 인물·별칭 사전 추출 → 요약 생성을 하고 앱을 엽니다. 손으로 만든 사전이 필요 없습니다.
- **파생 데이터 계층**: 원문 chunk 외에 장 요약·권 요약·인물 스냅샷이 생겼습니다. 모두 `Chunk`로 변환되어 원문과 같은 firewall·검증기를 지납니다.
- **시점 제한 생성**: 요약과 사전 모두 장 순서로 만들고 입력을 그 장까지로 제한합니다. 사전의 오류는 "늦게 연결되는 쪽"(안전한 쪽)으로만 나도록 설계했습니다.
- **작품별 데이터와 자동 무효화**: 파생 데이터는 `data/derived/<소설 파일 이름>/`에 저장되고, 원문이나 사전이 바뀌면 해시로 감지해 다시 만듭니다.
- **입력 형식 확장**: 텍스트 파일 하나뿐 아니라 PDF, 그리고 여러 파일로 나뉜 소설(폴더)을 받습니다. 모두 `sources.py`가 `# 권 / ## 장` 표기 하나로 합친 뒤 기존 파싱을 그대로 탑니다.
- **설정**: 기본 사전이 자동 추출 사전으로 바뀌었습니다. API 키와 사용할 소설은 `.env`로 지정합니다.

---

독자가 읽은 위치까지만 검색하고 답하는 소설 도우미입니다. 설계 기준은 [spoiler_safe_rag_project.md](spoiler_safe_rag_project.md)를 따릅니다.
이번 버전은 명세서의 **Phase 1**(원문 파싱·sequence 부여·진행도 필터 검색·근거 기반 답변·출처 표시)에 다음 기능을 일부 더했습니다.

- Phase 2: BM25 하이브리드 검색, 별칭 사전
- Phase 3: 장 요약·권 요약·인물 시점별 스냅샷(근거·생성 범위 기록), 인물 언급 타임라인, 첫 등장 조회
- Phase 5: 출력 검증기, 진행도 되돌리기 시 대화 격리, 질의 로그

## 실행

가장 쉬운 방법: 탐색기에서 **`run_app.bat`을 더블클릭**합니다. 소설을 준비(사전 추출 + 요약 생성)한 뒤 웹 UI를 브라우저에서 엽니다(창을 닫으면 종료). 준비는 처음 한 번만 오래 걸리고, 이후에는 이미 처리한 부분을 건너뜁니다.

```powershell
# 의존성 설치 (프로젝트의 .conda 환경 기준)
.\.conda\python.exe -m pip install -r requirements.txt

# (선택) Claude 답변 생성을 쓰려면 .env 파일에 API 키 설정
Copy-Item .env.example .env   # 그 뒤 .env를 열어 ANTHROPIC_API_KEY 값을 채우기

# 웹 UI
.\.conda\python.exe -m streamlit run app.py

# 명령줄
.\.conda\python.exe -m spoiler_rag.cli --book 1 --chapter 4 "회색 기사는 누구야?"

# 소설 준비: 구조 인식 → 인물·별칭 사전 자동 추출 → 요약·스냅샷 생성 (run_app.bat이 자동으로 실행)
.\.conda\python.exe -m spoiler_rag.prepare                                   # API 키 필요, 중간에 멈춰도 이어서 진행
.\.conda\python.exe -m spoiler_rag.prepare --compare data/sample_entities.json   # 자동 사전을 정답 사전과 비교
.\.conda\python.exe -m spoiler_rag.prepare --rebuild                          # 사전·요약을 처음부터
.\.conda\python.exe -m spoiler_rag.prepare --no-llm                           # API 없이 (사전 없음, 요약은 추출식)

# 테스트
.\.conda\python.exe -m pytest -q
```

API 키가 없어도 앱은 동작합니다. 이때는 Claude 대신 **검색된 근거 문단**을 그대로 보여 줍니다. 다만 인물·별칭 사전은 Claude로만 추출하므로, 사전이 없으면 인물 인식·인물 상태 기능은 꺼지고 검색·요약·스포일러 경계만 동작합니다. 요약 캐시가 없으면 앱이 시작할 때 추출식 요약을 메모리에서 만들어 씁니다.

## 인터페이스

Streamlit 채팅 UI입니다.

- 사이드바: 권·장 선택 → 진행도 저장(`data/progress.json`), 허용 범위 표시, 인물 사전 상태, Claude 사용 토글
- **아직 읽지 않은 권·장의 제목은 숨깁니다.** 장 제목도 스포일러가 될 수 있기 때문입니다(예: "마지막 등불").
- 답변마다 질문 유형, 생성 모드, 근거 문단(권·장, chunk ID)을 표시합니다.
- 진행도를 뒤로 돌리면 이후 범위에서 나눈 대화를 화면과 LLM 컨텍스트에서 제거합니다.

## 스포일러 방어선

| 단계 | 구현 |
|---|---|
| 색인 | 모든 chunk에 `sequence_start/end`가 있어야 하고, 위치 메타데이터가 없으면 색인 자체를 거부합니다. chunk는 장 경계를 넘지 않습니다. |
| 1차: 검색 | 벡터·BM25 모두 점수 계산 **전에** `sequence_end <= cutoff`로 후보를 자릅니다. BM25의 문서 빈도도 허용 범위 안에서만 계산합니다. |
| 1차: 별칭 | "회색 기사 → 카이든" 같은 연결은 `revealed_at` 이전에는 질의 확장·엔티티 조회에 쓰지 않습니다. |
| 1차: firewall | 모든 검색 경로의 결과를 한 번 더 검사합니다(메타데이터 없음·경계 걸침·미래 → 차단). |
| 2차: 생성 | `ClaudeGenerator`는 API 요청 직전에 다시 검사하고, 위반이 있으면 요청을 보내지 않고 예외를 냅니다. 프롬프트는 명세서 7.4를 따릅니다. |
| 3차: 검증 | 제공되지 않은 근거 ID 인용, 아직 등장하지 않은 이름, "나중에 밝혀" 같은 메타 표현을 검사합니다. 실패하면 1회 재생성하고, 다시 실패하면 중립 응답으로 대체합니다. |
| 메모리 | 대화 턴마다 생성 당시의 cutoff를 저장하고, 현재 cutoff보다 큰 턴은 컨텍스트에서 제외합니다. |

### 파생 데이터(요약·스냅샷)의 방어

요약도 스포일러가 될 수 있어서, 원문과 같은 방식으로 다룹니다.

- **생성**: 전체 소설을 한 번에 넣지 않습니다. 장을 순서대로 처리하고, 입력은 *그 장까지의 원문 + 이전 단계의 산출물*뿐입니다. 권 요약은 그 권의 장 요약만 입력으로 씁니다(계층적 요약).
- **기록**: 레코드마다 `generation_scope_end`, 근거 chunk ID, 모델, 프롬프트 버전, 생성 시각, 검증 상태(`verified`/`extractive`/`fallback`)를 저장합니다.
- **검증**: 생성된 요약에 아직 접하지 않은 이름이나 메타 표현이 있으면 1회 재생성하고, 그래도 실패하면 추출식으로 대체합니다(`fallback`, 사유 기록).
- **조회**: 파생 레코드는 `generation_scope_end`를 `sequence_end`로 갖는 `Chunk`로 변환되어, 원문과 같은 firewall을 지납니다. 장 중간까지만 읽었다면 그 장의 요약은 쓰이지 않습니다.
- **캐시 무효화**: 레코드에 "그 시점까지의 원문 누적 해시"를 저장합니다. 원문이 바뀌면 이후 모든 레코드가 오래된 것으로 판정되어 삭제·재생성됩니다.
- 인용 ID는 원문 `C`, 장 요약 `S`, 권 요약 `B`, 인물 스냅샷 `P`로 구분합니다.

### 사전 자동 추출의 방어

별칭 사전에서 가장 위험한 오류는 정체 공개 시점을 실제보다 **이르게** 적는 것입니다. 그래서 늦게 적히는 쪽으로만 틀리도록 만듭니다.

- **장 순서 추출**: N장을 처리할 때 모델이 보는 것은 N장 본문과 N-1장까지의 사전뿐입니다. 이후 본문을 본 적이 없으므로 미래 공개를 알 수 없습니다.
- **배운 장부터 연결**: 모든 이름·별칭에 그것을 확인한 장을 `revealed_at`으로 적습니다. 놓치거나 늦으면 정보가 적어질 뿐 유출되지는 않습니다.
- **추측 차단**: 이름·별칭은 그 장 본문에 글자 그대로 있어야 하고, 근거 문장도 본문과 대조합니다(작품에 대한 모델의 사전 지식으로 미래 이름을 적는 경우를 막음).
- **정체 공개 확인**: 이미 다른 대상의 호칭인 문자열을 새 대상에 연결할 때는 별도 확인 호출이 "본문에 명시적으로 서술됨"과 본문 그대로의 근거 문장을 내야만 받습니다. 암시만 있는 장면은 거부됩니다.
- **시점별 표시 이름**: 대상 이름을 보여 줄 때는 그 시점에 아는 이름만 씁니다(`display_name`). 정식 이름이 공개 전이면 먼저 알려진 호칭을 씁니다.
- **비교 도구**: `--compare`가 "일치 / 늦음 / 누락 / **이른 연결**(위험) / 정답에 없음"을 보여 줍니다.

답할 수 없을 때는 미래의 존재를 암시하지 않도록 항상 *"현재 읽은 범위의 근거만으로는 확인할 수 없어요."* 라고만 답합니다.

## 다른 작품 넣기

1. 소설을 예를 들어 `data/novels/`에 둡니다. 저장·처리 권한을 먼저 확인하세요.
   - **텍스트 파일**(UTF-8 또는 CP949): 문단은 빈 줄로 구분합니다. 장 제목 줄("제1장 …", "1장", "Chapter 1", "프롤로그")이 있으면 자동으로 인식합니다. 권까지 나누려면 `# 1권 제목` / `## 1장 제목` 표기를 씁니다. 장 제목이 전혀 없으면 30문단씩 자동으로 나눕니다.
   - **PDF 파일**: 장 사이의 구분 기호(◆, * * *, 글꼴에 없는 기호 등) 또는 장 제목 줄로 장을 나눕니다. 쪽마다 반복되는 머리글·바닥글과 첫 구분선 앞의 짧은 머리말은 빼고, 쪽 너비에서 끊긴 줄은 문단으로 다시 잇습니다. 위키문헌에서 인쇄한 PDF(예: 『무정』)는 장 구분 기호, 넓게 뽑힌 띄어쓰기, 낱말 중간 줄바꿈까지 맞춰 두었습니다.
   - **나뉜 파일**: 파일들을 한 폴더에 넣고 폴더를 지정합니다(.txt와 .pdf 섞어도 됨). 파일 이름의 숫자 순서로 읽습니다(`무정2_…`가 `무정10_…`보다 앞). 한 작품을 나눈 파일이면 장 번호를 파일을 넘어 이어 매기고, 파일마다 장 번호가 1부터 다시 시작하면 파일 하나를 한 권으로 봅니다.
2. `.env`에 `SPOILER_RAG_NOVEL=data/novels/파일이름.txt`(또는 `.pdf`, 또는 폴더 `data/novels/무정`)를 적습니다.
3. 먼저 구조만 확인합니다: `.\.conda\python.exe -m spoiler_rag.prepare --no-llm`. 파일별 장 범위, 본문에서 뺀 줄, 확인이 필요한 파일(파일 이름의 "1장~20장"과 나눈 장 수가 다른 경우)이 출력되고, 합친 본문이 `data/derived/<이름>/source_preview.txt`에 저장됩니다.
4. `run_app.bat`을 더블클릭합니다. 인물·별칭 사전과 요약이 자동으로 만들어진 뒤 앱이 열립니다.

손으로 만든 사전을 쓰고 싶으면 `.env`에 `SPOILER_RAG_ENTITIES=경로`를 적습니다(자동 추출 생략). 형식은 `sample_entities.json`을 따르고, 나중에 정체가 밝혀지는 별칭은 `{"text": "...", "revealed_at": {"book": 2, "chapter": 3}}`로 적습니다.

## 현재 한계와 다음 단계

- **임베딩**: 외부 의존성 없이 동작하는 문자 n-gram TF-IDF를 baseline으로 씁니다. 의미 검색 품질을 높이려면 `index.Embedder` 프로토콜을 구현한 다국어 임베딩 모델로 교체하세요. 벡터 IDF는 전체 원문 통계로 계산되는데, 순위에만 영향을 줄 뿐 미래 내용이 컨텍스트에 들어가지는 않습니다.
- **줄거리 요약**: 장 요약이 24개를 넘으면 끝난 권은 권 요약으로 대체합니다. 한 권이 아주 길면 그 권의 장 요약이 모두 들어가므로, 권 안을 다시 묶는 단계(예: 부 단위)는 아직 없습니다.
- **추출식 요약**은 원문 문장을 그대로 고르는 baseline입니다. 문장 선택이 거칠어서 자연스러운 요약은 Claude로 만들어야 합니다(`prepare`).
- **사전 자동 추출**은 Claude가 필요하고, 장 수에 비례해 호출이 늘어납니다(장마다 1회 이상, 정체 공개 후보마다 확인 1회). 정확도는 샘플 소설에서 가짜 추출기로만 검증했고, 실제 모델 결과는 `--compare`로 확인해야 합니다. 유명한 작품은 모델이 내용을 알고 있을 수 있는데, 본문 대조와 확인 호출로 막지만 완벽한 보장은 아닙니다. "등대", "일지" 같은 짧은 일반 명사 별칭은 다른 문맥에서도 걸려 검색 잡음이 생길 수 있습니다.
- **PDF 문단·띄어쓰기 복원**은 추정입니다. 짧은 줄과 여는 따옴표로 시작하는 줄을 문단 경계로 보므로, 줄 끝에 딱 맞게 끝난 문단은 다음 문단과 붙을 수 있습니다. 줄 경계의 띄어쓰기는 문서 안의 어휘로 판단해서 가끔 틀립니다(『무정』에서 "더치더라도" ← "더 치더라도" 같은 경우). 스캔 이미지 PDF(글자 없음)는 읽지 못합니다.
- **권이 하나인 긴 작품**(『무정』 126장): 장 요약이 24개를 넘어도 대체할 권 요약이 없어, 뒤쪽 장에서 줄거리 질문을 하면 장 요약이 모두 근거로 들어갑니다(100장 시점에 근거 102개). Claude 답변의 입력이 길어집니다.
- **장 제목 자동 인식**은 정규식 규칙이라, 특이한 장 제목 형식은 놓칠 수 있습니다(그 경우 자동 분할되거나 장이 합쳐짐). 작품 제목은 파일 이름을 씁니다.
- **사건 레코드**(명세서 5.5)와 **관계 레코드**(5.6, Phase 4)는 아직 없습니다. 장 요약이 시간순 사건 목록 역할을 대신합니다.
- **스냅샷 대상**은 `kind: character` 엔티티이며, 그 장에서 (시점에 맞게) 언급된 인물만 만듭니다. 인물 수 × 장 수만큼 API 호출이 늘어납니다.
- **라우터·검증기**는 규칙 기반입니다. 간접 스포일러는 이름·표현 수준에서만 잡아냅니다.
- **진행도 단위**는 장입니다. 문단 단위 진행도는 모델(`current_sequence`)이 이미 지원하므로 UI만 추가하면 됩니다.
- 진행도 저장소는 단일 사용자용 JSON 파일입니다.
